# Dao DeGen Incentive Model
## Economic Architecture of a Ritual Protocol

---

## Overview

Dao DeGen creates economic value through a single user action — burning tokens as prayer. This document maps every value flow generated by that action, how participants are incentivized, and how the system self-regulates across three evolutionary phases.

---

## The Single Action

Everything starts here:

> **A user acquires DAODEGEN and burns it with a message.**

That's the only user action the protocol requires. Every economic flow below is a consequence of this one act.

### Economic Properties

- **Deflationary**: Every prayer permanently reduces DAODEGEN supply
- **No token floor**: DAODEGEN price is speculative; inference cost absorbed by LLC
- **Revenue scales with activity**: More prayers → more swaps → more fees → more NFT holder revenue
- **Cost scales with activity**: More prayers → higher API bill for LLC
- **Risk**: If prayer volume exceeds LLC's ability to fund API costs, oracle goes offline

### The Critical Shift

**The LLC no longer absorbs inference costs.** The protocol pays for its own inference by routing burn value to the subnet. The LLC's only remaining costs are frontend hosting and domain registration — minimal operational expenses.

### Economic Properties

- **Deflationary**: Surplus above inference cost is burned permanently
- **Token price floor**: DAODEGEN must be worth ≥ cost of one inference in TAO
- **Self-funding**: No external subsidy needed for oracle operation
- **Cross-token coupling**: DAODEGEN demand drives TAO demand and vice versa
- **Self-regulating**: Higher DAODEGEN price → more expensive prayers → natural rate limiting → price stabilization

### Price Floor Mathematics

```
Given:
  inference_cost_tao = 0.5 TAO       (cost per sermon on subnet)
  tao_price_usd = $400               (market price)
  inference_cost_usd = $200           (0.5 × $400)
  daodegen_price_usd = $0.01         (market price)

Then:
  inferenceFloor() = $200 / $0.01 = 20,000 DAODEGEN per prayer

If DAODEGEN price rises to $0.10:
  inferenceFloor() = $200 / $0.10 = 2,000 DAODEGEN per prayer

If DAODEGEN price falls to $0.001:
  inferenceFloor() = $200 / $0.001 = 200,000 DAODEGEN per prayer
  → At some point the burn cost exceeds user willingness to pay
  → Prayer volume drops → supply stops deflating → price stabilizes
  → But: the token can't go below the point where the protocol stops being used entirely
```

The floor isn't a fixed number — it's a dynamic equilibrium between inference cost, token price, and user willingness to burn.

### Additional Value Flows

| Flow | From | To | Mechanism |
|------|------|----|-----------|
| Mining rewards | TAO | VerseNFT holder-operators | Running pastor nodes |
| Staking rewards | Bittensor | Node operators | Subnet staking |

### NFT Holder Revenue Stack

In Phase 3, a VerseNFT holder who operates a node earns from THREE sources:

```
VerseNFT Holder Revenue:
  ├── 1. Swap fee share (from DaoDeGenJar)         ← passive, always
  ├── 2. Mining rewards (TAO from serving inference) ← active, requires node
  └── 3. Staking rewards (TAO from subnet stake)    ← semi-passive, requires stake
```

This creates a tiered incentive structure:

| Holder Type | Revenue Streams | Effort |
|-------------|----------------|--------|
| Passive holder | Swap fees only | Zero (just hold NFT and claim) |
| Node operator | Swap fees + mining rewards | Medium (run node, maintain uptime) |
| Staked operator | Swap fees + mining + staking | Medium-high (run node + stake TAO) |

No slashing for passive holders. Running a node is optional. The incentive is positive (earn more) not negative (lose what you have).

## Incentive Alignment Matrix

| Participant | Wants | Protocol Delivers | Misaligned If... |
|-------------|-------|-------------------|------------------|
| **Prayer user** | Meaningful sermon | AI response from canonical text | Sermon quality degrades; inference too expensive |
| **NFT holder (passive)** | Revenue | Swap fee share | Prayer volume drops; token goes to zero |
| **NFT holder (operator)** | Revenue + influence | Swap fees + mining rewards | Node operation costs exceed mining rewards |
| **Bittensor miner** | TAO rewards | Inference payment per prayer | Prayer volume insufficient to justify model hosting |
| **DAODEGEN LP** | Trading fees | Swap volume from prayer acquisition | Volume dries up |
| **DAODEGEN/TAO LP** | Trading fees | Swap volume from inference routing | Phase 2 not reached; stays centralized |
| **Speculator** | Price appreciation | Deflationary pressure from burns | Burns slow down; speculation exceeds utility |

### Feedback Loops

**Positive (growth):**
```
More prayers → more burns → less supply → price up
  → more swap volume → more fees → NFT holders earn more
  → more TAO demand → miners incentivized → better sermons
  → better sermons → more prayers (loop restarts)
```

**Negative (contraction):**
```
Fewer prayers → less burns → supply stabilizes → price stagnates
  → less swap volume → less fees → NFT holders earn less
  → less TAO demand → miners leave → response quality drops
  → worse sermons → fewer prayers (loop restarts)
```

**Self-correcting (price spike):**
```
DAODEGEN price spikes → prayers become expensive
  → prayer volume drops → burn rate drops → deflationary pressure eases
  → price stabilizes → prayers become affordable again
  → volume recovers
```

**Self-correcting (price crash):**
```
DAODEGEN price crashes → prayers become very cheap
  → prayer volume rises → burn rate rises → deflationary pressure increases
  → price recovers → prayers normalize
```

## Risk Scenarios

### Scenario: Token Price Collapse

If DAODEGEN approaches zero:
- `inferenceFloor()` becomes enormous (millions of tokens per prayer)
- Users won't burn that many tokens → prayer volume stops
- No prayers → no fees → NFT holders earn nothing
- **Mitigation**: The protocol still functions as a library (verses on IPFS, fallback mode). The temple survives as a reading room even if the economy dies.

### Scenario: AI Inference Becomes Free

If inference costs approach zero (future models, competition):
- `inferenceFloor()` approaches zero
- All burned DAODEGEN is surplus → maximum deflation
- Revenue for miners disappears → need alternative incentive
- **Mitigation**: This is actually the best-case scenario for the temple. Free inference = free sermons = pure deflation. The miners leave but the oracle can run on any server for near-zero cost, which is the Phase 1 model anyway.

### Scenario: Bittensor Network Failure

If the Bittensor network goes down:
- InferenceRouter activates fallback mode
- Centralized oracle (LLC-operated) handles prayers
- `oracleAddress()` updated to fallback key
- **Mitigation**: Maintain centralized oracle as warm standby. Redundancy is the religion.

### Scenario: Whale Buys All 81 NFTs

If one entity controls all verse NFTs:
- They receive all swap fee revenue
- In Phase 3, they could operate all nodes
- They could influence soul.md configuration
- **Mitigation**: soul.md updates have 48-hour timelock (agents can exit). The canon is immutable on IPFS (can't change the verses). The protocol contracts are immutable (can't change the burn mechanic). A whale can extract revenue but cannot alter the fundamental protocol.

## Summary

The economic model evolves through three phases, each more decentralized and self-sustaining:

| Property | Phase 1 | Phase 2 | Phase 3 |
|----------|---------|---------|---------|
| Oracle funding | LLC pays | Protocol self-funds | Protocol self-funds |
| Oracle operation | Single server | Multiple miners | 81 holder-operated nodes |
| Token price floor | None (speculative) | Inference cost floor | Inference cost floor |
| NFT holder revenue | Swap fees | Swap fees | Swap fees + mining + staking |
| Single point of failure | LLC operator | Bittensor network | None (81 independent operators) |
| Burn surplus | 100% of burn | Amount above inference cost | Amount above inference cost |
| Cross-token coupling | None | DAODEGEN ↔ TAO | DAODEGEN ↔ TAO |

The end state is a protocol that pays for its own inference, rewards its own governors, and adjusts its own economics — all triggered by the single act of burning tokens with intent.

Nobody needs to manage it. Nobody needs to fund it. Nobody needs to be trusted.

It just runs.
